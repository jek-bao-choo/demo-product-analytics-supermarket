## Where things stand

**Done, and live on https://main.deiozh6jsqyzm.amplifyapp.com (Amplify job 5, commit `27db25d` on `main`)**
- `/` is a directory linking to two two-level stores:
  - **Supermarket:** `/supermarket/` → `/supermarket/category/snacks--confectionery/`
  - **Furniture Mart:** `/furniture-mart/` → `/furniture-mart/category/sofas-armchairs/`
- **RUM:** 100% of sessions.
- **Session Replay:** 100% of sessions, with `defaultPrivacyLevel: 'mask-user-input'`.
- **Visitor id:** a random id per browser, kept in localStorage (`app/visitor.js`). It is sent as RUM `usr.id` and used as the flag `targetingKey`.
- **Feature Flags:** the Datadog provider starts in `instrumentation-client.js`. Each store's home page reads one flag to pick its lead hero banner:
  - `supermarket_hero_campaign`: `free-gift-tote` (control), `snack-fest`, `weekly-deals`
  - `furniture_mart_hero_campaign`: `make-room-to-celebrate` (control), `sofa-week`, `cosy-corners`
- **Click names** for experiment metrics: `Hero banner: <slide id>` and `Add to cart`.
- **`store` global context:** `supermarket` or `furniture-mart` on every event from a store page.

**Checked on the live site, before any Datadog UI setup**
- Datadog accepts the site's RUM and Session Replay data.
- The flags request succeeds and is served from the Datadog flag environment **Staging**. The site sends `env: demo`, and Datadog maps that to Staging.
- Staging serves only 1 flag, which existed before this work. Neither new flag is there yet, so every visitor sees the control banner.

**Facts worth remembering**
- **Remote Configuration** (`NEXT_PUBLIC_DD_REMOTE_CONFIG_ID`) exists but is empty, so the sample rates and privacy level in code apply. If values are ever set there, they override the code.
- **The Amplify app has no Git connection.** Deploy with `bash scripts/deploy-amplify.sh`. It builds with `.env.local`, uploads the build and waits for the job to finish. If it fails with "last job was not finished", cancel the stuck PENDING jobs with `aws amplify stop-job`.
- **`AGENTS.md`** is generated by `next dev` and is intentionally not committed.

## To do in the Datadog UI

Full click-by-click steps are in README → "Session Replay, Feature Flags and Experiments".

1. **Enable Product Analytics:** Digital Experience → Manage Applications → app → Product Settings → Product Analytics → Enable.
2. **Create both flags** at https://app.datadoghq.com/feature-flags/create:
   - Use the keys above, exactly.
   - Variant type **String**.
   - Variant **values** must equal the slide ids above.
   - Include the browser / client-side SDK distribution channel.
3. **Create the metrics** under Product Analytics → Experiments → Metrics → Create Metric. Use aggregation *Count of unique users* for all three:
   - **Reached level 2:** views of `/supermarket/category/snacks--confectionery` or `/furniture-mart/category/sofas-armchairs`.
   - **Hero banner clicks:** actions named `Hero banner: *`.
   - **Add to cart:** actions named `Add to cart`.
   - The filter properties are probably `@view.name` and `@action.target.name`; type them in *Custom property* if they're not listed.
4. **Create one experiment per flag** from the flag page: Targeting rules & rollouts → Create New Experiment.
   - **Subject:** User (`@usr.id`).
   - **Environment:** **Staging**.
   - **Variants:** control vs `snack-fest` (Supermarket) or `sofa-week` (Furniture Mart), split Equally.
   - **Traffic exposure:** 100%.
   - Click **Start Experiment & Enable Flag**.
